# Round 1 Teardown — Carbon (`spec-v1.md`)

## Findings

### 1. [BLOCKER] Raw `chatId` / snowflake ops bypass `assertSameSwarm` (cross-swarm leak)
- **Problem:** `assertSameSwarm` covers only `bus_post`, `channel_*`, and PR4 `assign`/`answers` (`spec-v1.md:34-35,66`). `fetchMessages` (`src/ws.ts:931,1153`), `reply` (`src/ws.ts:893,1020`), `react` (`src/ws.ts:910,1046`), `editMessage` (`src/ws.ts:917,1090`), `downloadAttachment` (`src/ws.ts:924,1112`), and `askUser` (`src/ws.ts:938,1173`) pass raw channel IDs straight to `fetchTextChannelOrNull`—any `cfd` agent can read history, pull attachments, edit bot messages, or post in `bus`/`default`. `channelOps.resolve` (`src/router.ts:215-217`) resolves `<#id>`/snowflakes without swarm checks; `channel_unsubscribe` and `channel_archive` (`src/ws.ts:1862-1876`, `channel`+`replacement`) are missing from `spec-v1.md:34`; `reply`/`permissionRequest` fall back to global `activeChatId` (`src/router.ts:97`, `src/ws.ts:1020,1318`); `reply` redirects only `deps.busChannelId` (`src/ws.ts:903`), not `<id>:general`.
- **Fix (spec text):** *"Every channel-bearing frame (`channel_*` including `unsubscribe` and `archive` [`channel`+`replacement`], `fetchMessages`, `reply`, `react`, `editMessage`, `downloadAttachment`, `askUser`, `permissionRequest`) enforces `channelSwarm(id) === caller.swarm || isCrossSwarm(caller)`, else `cross_swarm`. `reply` to `swarmChannels(s).general` redirects to `busPost`; `activeChatId` fallback applies only to `default`."*

### 2. [BLOCKER] Inbound routing drops `<id>:general` / `<id>:human` and misroutes `bus_post` & `to="human"`
- **Problem:** (a) `handleInbound` (`src/router.ts:432`, PR #26 `src/router.ts:495`) calls `handleBusInbound` only for `BUS_CHANNEL`, `HUMAN_CHANNEL`, `directChannelOwner`, or `subs.channels()`. Non-default `<id>:general`/`<id>:human` aren't in `subs`, so Mick's posts hit `gate()` (`src/access.ts:204`) and drop; `everyone` (`src/router.ts:413`) is also `false`. (b) Reply-to-bot (`src/router.ts:394-400`) parses bare `**[asker → ...]**` unscoped, hitting the wrong swarm on duplicate names. (c) `handleBusPost` (`src/ws.ts:1434`), `postToChannel` `to="human"` (`src/ws.ts:1589-1594`), and PR #26 `agentPostError` (`src/ws.ts:1471`) hardcode global `deps.busChannelId`/`deps.humanChannelId`.
- **Fix (spec text):** *"`handleInbound` routes any channel with `channelSwarm(msg.channelId)` to `handleBusInbound`, setting `everyone = true` on every swarm's `general`/`human` channels. Reply-to-bot (`router.ts:394`) scopes `asker` to `channelSwarm(msg.channelId)` unless `inboxes.approvalTarget(ref.id)` binds a cross-swarm sender. `bus_post` uses `swarmChannels(caller.swarm).general`; `to='human'` redirect/copy and PR #26's `to=human` guard use `swarmChannels(channelSwarm(channelId)).human`."*

### 3. [BLOCKER] Unscoped name-keyed tables collide across swarms on day 1
- **Problem:** `start-agents.sh:33,42` starts windows in `~/src`, creating identical `<agent>@<host>:src` names across swarms. Spec (`spec-v1.md:36-45,66`) misses: (a) task `Claims` (`src/nodes.ts:72-106`, `src/ws.ts:691-701`)—`list_claims` leaks all swarms' tasks and `(cfd, claude@mac:src)` overwrites/releases `(default, claude@mac:src)`'s claims; (b) `Subscriptions` (`src/subscriptions.ts:21-24,90-108`)—bare `name` keys corrupt `owners`/fan-out; (c) `deps.inboxes?.target(name)` (`src/ws.ts:646,834,889`)—a native agent in `default` sends `replaced` to `(cfd, claude@mac:src)`; (d) `SessionManager` (`src/sessions.ts:27-46`, where `instanceId` dedup uses local PID `src/plugin.ts:131`, colliding across hosts/`tmux move-window`), `pullSessions` (`src/ws.ts:156`), `busPostTimes` (`src/ws.ts:1415`), `Unread`/`CostClasses`/`Conversations`/`Activity`/`WakeBudget` (`src/wake.ts:31-172`), and `RULES_SEEN` (`src/router.ts:176-188`).
- **Fix (spec text):** *"Key all session-scoped state by `(swarm, name)` (defaulting `swarm='default'` internally): `SessionManager` (`extraSends` dedup keyed by `(swarm, host, instanceId)`), `Subscriptions`, task `Claims`, `Inboxes` (`aliases`, `legacyConversations`, `seenAliases`, publish dedupe key), `pullSessions`, `busPostTimes`, `Unread`, `CostClasses`, `Conversations`, `Activity`, `WakeBudget`, and `RULES_SEEN`."*

### 4. [BLOCKER] Registration rule (`spec-v1.md:26` vs `32` vs `51`) contradicts itself and leaks typos into `default`
- **Problem:** Wire frame is `register` (`src/types.ts:21`), not `hello` (`spec-v1.md:25,87`). `spec-v1.md:26` ("unknown value → `default`") contradicts `spec-v1.md:32` ("first sight creates category `<id>`"): mapping unknown values to `default` prevents new swarms from provisioning, whereas auto-creating categories for arbitrary tmux sessions (`0`, `scratch`, `archive`, `agents`) breaks `spec-v1.md:51` (back-compat when unset) and collides with `archive`/`Agents` categories (`src/router.ts:243`, PR #26 `src/router.ts:256`). Silently mapping unknown swarms to `default` leaks misconfigured swarms into `default`.
- **Fix (spec text):** *"`WsRegister` adds `swarm?: string`. Missing/`''`/`'default'`/`'agents'` → `'default'`. When swarm config is unset, all values → `'default'`. When set, `swarm` must match `/^[a-z0-9][a-z0-9-]{0,31}$/`, exclude `agents`/`archive`, and appear in swarm config (empty candidate lists allowed); undeclared values fail closed (`register rejected: unknown_swarm`)."*

### 5. [BLOCKER] PR4 contradicts PR #26 direct channels, A10 v2 candidacy/queuing/topic rules, and `demote`
- **Problem:** Five conflicts with `a10-v2-draft.md` (`r9-neon.md`) and PR #26: (a) `spec-v1.md:74` routes untagged human posts in **any** `<id>:*` channel to `<id>`'s master, breaking PR #26 `<id>:<agent>` direct channels (`src/ws.ts:1850` on PR #26); (b) `pickCoordinator → alias | undefined` (`spec-v1.md:64`) misses A10 v2's 3 states (`a10-v2-draft.md:12,19-22`, `r9-neon.md:8`): `deliver(master, term)`, `queue` (30 s restart hold or standby failover), and `fallback` (live **interactive** push sessions only, `src/ws.ts:1712`); (c) `spec-v1.md:71,84-96` omits `role:'master'` on `register` and PR6b plugin tools (`DISCORD_ROLE=master`, `assign`, `answers`, `term` meta; `a10-v2-draft.md:7,43`), misfiring `not_master_candidate` on normal workers like `claude@nas642:src`; (d) `spec-v1.md:75` omits topic-subscriber checks on `assign` (`a10-v2-draft.md:19,29`, `r9-neon.md:12`); (e) `demote <alias>` (`spec-v1.md:73`) is ambiguous when one alias is candidate in two swarms (`spec-v1.md:81`).
- **Fix (spec text):** *"Direct `<id>:<agent>` channels bypass master routing. Change seam #5 to `routeCoordinator(swarm, msg) → {action:'deliver', master, term} | {action:'queue'} | {action:'fallback'}` (`fallback` uses `liveMembers(swarm, {interactive:true})`). Include PR6b in PR4; check candidacy only when `register.role === 'master'`. Require topic `assign` owners to be subscribers. Scope `demote` by `channelSwarm(msg.channelId)` or `demote <swarm> <alias>`."*

### 6. [BLOCKER] `DISCORD_SWARMS` env grammar collides with `:` in aliases and cannot hot-reload
- **Problem:** Aliases contain `:` (`codex@nas642:cfd-lead`, `src/bus-alias.ts:6`), making PR4's `:1` suffix (`spec-v1.md:71`) vs PR1's unsuffixed aliases (`spec-v1.md:29`) ambiguous (`claude@mac:2`). `spec-v1.md:55` requires immediate reload, but `process.env` is static and `loadEnvFile` (`src/router.ts:30`, `src/access.ts:293`) runs once without overwriting set vars (`r9-neon.md:10`). `default`'s PR4 allowlist is unspecified (`spec-v1.md:30,82`).
- **Fix (spec text):** *"Load `${STATE_DIR}/swarms-config.json` (`{[swarm]: {candidates: [{alias, priority}]}}`, including `'default'` in PR4), hot-reloaded via `mtimeMs:size` like `Grants.reload` (`src/mcp.ts:143-170`), with `DISCORD_SWARMS` env as startup-only fallback using `#<priority>`."*

### 7. [BLOCKER] Plugin wake breaks `agents` (`"agents" !== "default"`) and `tmux move-window` never reconnects
- **Problem:** (a) `spec-v1.md:88` maps `agents` → `SWARM_ID='default'`, then `spec-v1.md:91` checks `#{session_name} === SWARM_ID` before `send-keys`—`"agents" !== "default"`, breaking wake in `agents`. (b) `tmux move-window` (`spec-v1.md:94-95`) keeps the WS open, stranding the plugin in the old swarm while `flushWake` (`src/plugin.ts:350-372`) fails. (c) `findTmuxPane` (`src/plugin.ts:224,319-320`) runs only when `wakeMode==='tmux' && !wakePane`; `TMUX_PANE` misassigns daemons spawned inside tmux. (d) PR #27 `assignedAlias` (`src/plugin.ts:312` on PR #27) keys only by `instanceId`, carrying `-2` across swarms.
- **Fix (spec text):** *"Check `normSwarm(paneSession) === swarmId` (`normSwarm(s) = (!s || s === 'agents') ? 'default' : s`) before `send-keys`. Always detect own pane via `findTmuxPane` (live PID walk, never `TMUX_PANE`). Poll `#{session_name}` in the 10 s timer (`plugin.ts:1018`); on change, clear `assignedAlias` (or key by `${swarm}:${instanceId}`), close `currentWs`, and reconnect."*

### 8. [BLOCKER] PR 3 (`start-agents.sh` & `~/.codex-<id>`) breaks CLI args, Codex auth/MCP, and daemon restarts
- **Problem:** (a) `start-agents.sh:16-22` iterates single tokens (`for a in "$@"`), so `--swarm cfd` sets `HOST=cfd` and aborts (`start-agents.sh:48`). (b) `CODEX_HOME=~/.codex-<id>` (`spec-v1.md:101`) lacks `auth.json` and `config.toml` (`mcp_servers.discord`, `DISCORD_WAKE=tmux`, `SWARM_ID=<id>`), and `mac` (`start-agents.sh:45`) omits `CODEX_HOME`. (c) `--restart-codex-daemons` (`start-agents.sh:55-71`) refuses whenever another swarm runs Codex (`foreign=1`), or `pkill -f '[a]pp-server-daemon/releases'` kills every swarm's daemon.
- **Fix (spec text):** *"Parse `--swarm <id>` with `shift 2`. For `$S != agents` on `mac`/`nas642`, set `CODEX_HOME=~/.codex-$S`, symlink `~/.codex/auth.json`, render `config.toml` (`SWARM_ID=$S`, `DISCORD_WAKE=tmux`), and scope `--restart-codex-daemons` to that `CODEX_HOME`."*

### 9. [MAJOR] `DISCORD_CROSS_SWARM` spoofing and one-way reply deadlock
- **Problem:** `DISCORD_CROSS_SWARM` and coordinator/master candidates aren't in `protectedRenameAlias` (`src/ws.ts:443-452`), allowing `register`/`bus_rename` spoofing. `listSessions` (`src/ws.ts:793-815`) and `bus_sessions` (`src/plugin.ts:898-900`) omit `swarm`. When `swarm-master`/`ops-tmux-fixer` (in `default`) messages `(cfd, agent)`, `(cfd, agent)` cannot reply `to="claude@mac:ops-tmux-fixer"` (`assertSameSwarm` throws `cross_swarm`, `spec-v1.md:46,66`).
- **Fix (spec text):** *"Protect `DISCORD_CROSS_SWARM` and candidate aliases in `protectedRenameAlias`; grant cross-swarm only when `!ws.data.renamed` and `session.swarm === 'default'`. Include `swarm` in `listSessions`. Resolve `channel_post` `to` in `channelSwarm(channel)` plus allow targeting live `DISCORD_CROSS_SWARM` aliases from `<caller.swarm>:*`."*

### 10. [MAJOR] Category creation race, incomplete `SwarmStore`, and global `channelOps`
- **Problem:** Concurrent startups race on "first sight" (`spec-v1.md:32`), creating duplicate categories/channels. `SwarmStore` (`spec-v1.md:56`) omits `<id>:<topic>`, overflow, and archive categories; `channelOps.resolve` (`src/router.ts:217`) matches `c.name` globally and `channelOps.archive` (`src/router.ts:243`) uses one global `'archive'` category.
- **Fix (spec text):** *"Serialize per-swarm provisioning via in-memory promise lock and reconcile guild channels first. Persist `topics` and `channelToSwarm` in `SwarmStore`. Scope `ChannelOps` by `swarm`, archiving non-default channels to `<swarm> (archived)`."*

### 11. [MAJOR] Back-compat & headless/slash-command gaps (`inboxes.jsonl`, `name-leases.json`, `node.ts`)
- **Problem:** Bare keys in `inboxes.jsonl` (`src/inboxes.ts:89`), `name-leases.json` (`src/name-leases.ts:45`, gated by `isBusAlias`), `subscriptions.json`, `claims.json`, and `agent-channels.json` orphan mail/leases without migration. `registerNode` (`src/node.ts:348`), `registerAgent` (`src/types.ts:419`), and `inboxCount`/`agentStatus` (`src/node.ts:300,336`) lack `swarm`. Slash commands (`src/slash-commands.ts:151,255-393`, `src/ws.ts:957`) act globally. `HumanMail` (`src/wake.ts:69-86`) is non-durable/global (200 cap), and moving fallback notices out of `msg.channelId` (`spec-v1.md:48` vs `src/router.ts:427`) breaks `default` parity (`spec-v1.md:51`).
- **Fix (spec text):** *"Migrate bare persisted keys to `'default'` on load (`name-leases.json` v2 `{version:2, swarms:{...}}` reading v1 into `'default'`). Add `swarm?: string` to `registerNode` agents, `registerAgent`, `inboxCount`, and `agentStatus`. Scope slash commands to `channelSwarm(interaction.channelId) ?? 'default'`; ignore non-default `registerSkills`. Partition `HumanMail` per swarm in PR1, journal undisposed posts in PR4, and keep `msg.reply` in `msg.channelId`."*
