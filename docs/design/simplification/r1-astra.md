# Round 1 · Astra · Cuts to bus v4

I would cut two proposed features before PR6 starts and simplify five pieces of shipped or proposed code. I read the nine PR diffs and the design at `25c62a7`, whose native-IPC document is identical to `89be20c`. Ranges below are inclusive and refer to the named PR head. Savings are estimated net physical source lines after replacement, excluding tests. Stacked PRs count once. Design-only cuts get zero credit for existing code.

1. **Give the elected master one assignment operation.** Drop A10’s separate on-behalf-of claim request followed by an in-channel assignment post. Extend the existing dispatcher operation to take the human message ID, one owner and the current term. The router verifies the caller is the elected master, checks the term and topic membership, and records the owner and pending delivery together under the original message ID. It can then deliver the saved human message and display the assignment in-channel. A retry returns the recorded owner and completes any pending delivery once. A new master sees prior assignments. Keep ordinary self-claims for directly addressed work. **0 existing LOC; avoid an estimated 20–35 LOC** for the second wire operation, argument validation and client call. The existing dispatch already authenticates the dispatcher, resolves exact names and forwards router-held human provenance (#20, `src/ws.ts` 1671–1707). The BBQ failures justify election, two hosts, term fencing and one owner. Two separate writes add a crash window between claiming and notifying. Keep the failover queue, the no-live-candidate broadcast and stale-term rejection. Test a crash after the assignment commit and before delivery. This requires durable assignment state; the existing 200-message in-memory human-mail cache alone cannot provide it.

2. **Drop the proposed Claude recipient-token route.** Delete token collection, in-memory custody, hook-based refresh after restart and token rejection/re-registration from the Claude implementation brief (§2, lines 38–50, and A1). Use the session’s configured channel, or send as the gateway through the documented external-sender route. A held or declined wake leaves mail available through the addressed inbox. **0 existing runtime LOC** in #12–#20; approximately **6–9 design lines** can go or be rewritten. #16 explicitly excludes Claude. The recorded 2.1.33x tests already demonstrate both external delivery and the recipient hold. The trade is explicit: a plain bypass-mode session can wait for approval or its next inbox check. That gives up unattended wake in that case and preserves sender identity. It removes no deployed Claude capability. This is my recommendation on Mick’s open Q1.

3. **Retire the redundant gateway `mark` and per-item `ack` requests.** The router already journals `uncertain` before sending a wake (#20, `src/ws.ts` 193–207). The gateway then asks it to journal the same transition again (#19, `gateway.ts` 80–84 and `router-link.ts` 32–34). Drop that callback. The MCP client acknowledges by echoing its receipt on the next lease; it never calls `RouterLink.ack`. Remove that client method too. **About 8–12 LOC immediately, 23–30 total** after retiring the two v1 receive cases (#20, `ws.ts` 548–559 and `inboxes.ts` 428–432). Keep the v1 handlers through any mixed-version rollout until their callers are retired. Preserve the router’s internal journal ACK, receipt ownership and expiry checks, the gateway’s pre-send disk write, and terminal-result replay. A disconnect after native enqueue still takes the existing reconcile path. This cut also removes a redundant synchronous router journal write from an ordinary wake.

4. **Use one registry of conversations on each host.** #16’s `src/gateway/registry.ts` 14–83 maintains three indexes with hand-written unlink and removal. Keep the map keyed by native identity and the registration generation. Derive alias and parent-PID matches by scanning its values. On replacement, remove the old alias binding and enforce one record per identity before publishing the new generation. **About 28–38 LOC** from that 70-line class. The observed fleet had 19 connected sessions across hosts. A per-host lookup can afford that scan. A shared daemon must still return *all* matching conversations for the per-call metadata check. Keep the same-directory, alias-rebind, PID-reuse and stale-generation tests. This also removes the possibility of one index retaining an entry the others have dropped.

5. **Remove the host’s mutable adapter-factory registry and optional-module loader.** #16’s `src/gateway/host.ts` 37–87 registers the same two built-in factories immediately before looking them up. Construct the two supported kind/transport pairs directly from the validated bindings. Keep the `startHost({adapters})` injection point for tests. Once #16 and #17 ship together, use a normal import for `NativeDiscovery` in lines 345–368 and keep the explicit no-bindings configuration. **About 20–30 LOC.** There is no in-tree production caller adding a third factory. Duplicate or unsupported pairs must still fail startup. An explicit OpenCode descriptor must still win; otherwise use the verified per-conversation descriptor or the configured default, selected once before I/O. The two-independent-service regression is the test to retain.

6. **Share kernel credential decoding and keep two verification contracts.** In #16’s `src/gateway/peer-cred.ts` 120–139 and 151–195, both readers decode the same Linux socket credential or the same two Darwin socket options. Read and validate the peer PID, UID and returned lengths once per implementation path using one helper per OS. Discovery then reads the daemon’s own identity. Pipe authentication additionally requires its parent PID and start time, the registered parent, and the installed executable. **About 12–20 LOC.** The real Mac launchd-parent regression is the boundary: daemon discovery must succeed when PID 1 metadata is inaccessible, and a pipe whose parent cannot be verified must still fail. Keep both regression cases and the security reviewer’s veto.

7. **Track router replies in one table.** #19’s `src/gateway/router-link.ts` 10–14, 36–40 and 67–110 keep separate maps for tool requests and wake-result acknowledgements. Send `wakeResult` through the existing bounded request path. On success call `markReported`; on timeout, send failure or disconnect, leave the disk row unreported for replay after registration. **About 6–10 LOC** and one less piece of reconnect state. Currently `failPending` clears only the tool waiters, so an acknowledgement lost on a dead connection can leave its request ID in memory. A late reply must never mark a different attempt reported. Keep the cold-restart test that drops the acknowledgement and checks registration precedes replay.
