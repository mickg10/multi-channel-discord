# Round 4 · Astra

**Reject #12 as a universal rule. Accept #9’s router-side term check.** The distinction is which process answered the ping. I checked the ledger through `892ce49`, both dissenting briefs, and the PR heads. LOC estimates below are net non-test source lines. For unbuilt features I give the existing saving separately from the estimate of work avoided.

- **#12 — accept removing a separate renewal RPC for a directly connected candidate.** Use one router-owned WebSocket watchdog if the connection shares the candidate’s lifetime. #20 `src/router.ts` lines 299–338 wires open, message and close. It sets no explicit ping/pong deadline. A close callback alone cannot establish the promised 30-second bound. Start the clock at the last verified pong, include the ping interval in the bound, and fence the expired connection before promotion. Acceptance test: black-hole the active link immediately after a pong, keep the standby healthy, and require exactly one promotion within 30 seconds. A heartbeat establishes reachability; it cannot establish that an LLM turn is making progress.
- **#12 — reject using the host gateway’s pong as the master’s lease.** Stop only the master conversation and leave its gateway and a second conversation on that host running. The gateway can pong indefinitely. #16 `discovery.ts` lines 406–424 retains bindings on missing or incomplete listings. `Gateway.release()` is explicit, and #20 `ws.ts` lines 522–531 gives up durable alias ownership when it is called. Calling it on a probe timeout could expose the alias to takeover. For the first rollout, allow direct candidates with the watchdog above. Admit a multiplexed candidate once the gateway can attest the **specific conversation** under a current process identity and the router can expire that attestation within 30 seconds. The existing heartbeat can carry this evidence. Expiry withdraws candidacy while preserving the inbox binding. Test a disappearing conversation with a healthy gateway, a shared daemon that stays alive, and a live remote standby. Mail queues through promotion; broadcast is reserved for the no-live-candidate case. **0 existing LOC saved.** I would not book Neon’s 40–60 projected lines for multiplexed masters until this test passes.
- **#9 — keep the election term on `assign`; drop worker-side term tracking.** Sticky election still permits A → B → A when B subsequently leaves. B can answer the human directly, leaving no assignment row. A delayed request from A’s first tenure would then pass both the current-alias check and message-ID deduplication. Echo the term delivered with the original work. At the router, compare it with the persisted current term and the authenticated incumbent immediately before committing the assignment, with no asynchronous gap. Retry the old request after re-election and after router restart: expect zero new owners and zero deliveries. Retrying a committed current-term request must still return its recorded owner. **About 5 projected LOC retained** for the field and comparison; no per-worker election state.

## Further cuts

- **#14 — remove AGY language-server credential collection for human-operated TUIs.** Strike the SessionStart and per-turn hooks that harvest the LS address and CSRF credential solely to call `GetConversation` for `runState` (§2 AGY row, §5, R6 and §6). The observed failure is a human starting input between an IDLE observation and a tmux send. Faster polling or refreshing the credential cannot close that gap. Keep those TUIs pull-only and keep the addressed inbox. A separately approved gateway-owned ACP worker has its own session ID and turn events. This cut requires no change to a CFD session. **0 existing runtime LOC; roughly 30–60 avoided** for hook handling, credential refresh and the status request.
- **#15 — strike the optional loopback HTTP MCP server.** Remove “or gateway loopback HTTP” from the Codex tool transport in §3 and the architecture diagram. Two real same-directory Codex conversations already exercised one compiled stdio pipe per MCP connection, per-call thread metadata, owner denial and isolated inbox reads. That path covers the actual failure of a caller naming the wrong conversation. Loopback TCP would need its own way to authenticate the caller. Codex’s native enqueue socket and OpenCode’s HTTP service both remain necessary. **0 existing runtime LOC; two design edits and roughly 30–50 listener, lifecycle and authentication LOC avoided.**
- **#16 — retire the alternate verified-socket callback left over from the gateway skeleton.** #19 `gateway.ts` lines 25–27 and 170–188 lets an injected handler take the authenticated socket and a connection-time list of agents. The shipped CLI supplies no handler. Its normal MCP path already resolves the parent PID, start time and conversation on every call. Remove the override, its host option, and the snapshot in the success verdict. Keep the admission check that at least one registered parent matches. Replace the callback test with a real MCP call before and after rebinding on the same pipe. The latter must refuse the old conversation. **About 5–9 existing LOC saved** across `gateway.ts`, `host.ts` and `peer.ts`. There is then one post-authentication path to audit for the observed stale-session failure.
- **#17 — fold native `busPost` into the existing gateway operation dispatcher.** #20 `ws.ts` lines 572–593 constructs a second sender context solely for this one operation. #19 `router-link.ts` lines 54–60 emits a special frame for it. Add the operation to the existing allowlist and use its verified sender context. Pass the native `Target` through the legacy `busPost` handler at #20 lines 720–729 so deduplication and reply ownership stay conversation-bound. Preserve native text-only arguments, legacy attachments, and request-correlated errors. During mixed-version operation translate the old authenticated frame at entry. Test both spellings with the same sender and publish ID: one committed message and one mirror, including after a lost reply. **About 4–8 existing LOC saved once the compatibility translation retires**, plus one fewer native wire operation. This preserves #20’s human-topic copy and the recipient’s approval decision.
